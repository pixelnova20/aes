# 系统监控

超级管理员在服务门户点击“系统监控”，或登录后访问 `/monitor`。普通教师、助教和学生无法访问该页面或其 `/api/admin/monitor` 接口。

页面每 5 秒刷新，展示：

- 主机 CPU 利用率、可用内存、Swap、系统负载及生产数据所在文件系统的剩余空间。CPU 使用率由相邻采样的 CPU 时间差计算，内存使用率按 Linux 的 MemAvailable 计算。
- Courseworks 准入器的 CPU、内存和 QEMU 并发预算、已分配量、剩余量，以及等待请求和受管容器数量。预算是任务配额，不等于容器当前实际消耗，也不包含其他系统服务的配额。
- 最近 5 分钟有成功请求的用户、使用模块、最近请求时间，以及仍在运行的 Agent 任务和受管容器。用户可能同时使用多个模块。打开页面但长时间没有请求的用户不一定出现在近期活动列表；后台任务则独立计入。页面不将此人数称作精确在线人数。

数据来自已有操作日志、MySQL 任务状态及当前后端的资源准入器和容器登记表。Homeworks 的 SQLite 用户编号会转换为统一账户编号。接口只提供账户身份和资源状态，不返回聊天内容、源码、API Key 或容器环境变量。

活动日志读取有上限：每次最多读取最近 32 个相关日志文件，每个文件尾部最多 1MiB。日志不可读或繁忙导致截断时，页面会显示提示；人数可能偏低。整个快照缓存 5 秒，并合并并发采样请求。接口失败时，页面保留上次结果并标记连接异常。

当前实现适用于单台 AES 后端。若未来运行多个后端副本，需要汇总各实例的资源准入状态。新增功能不改变资源调度策略，不要求数据库迁移。
