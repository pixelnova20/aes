你现在是一个操作系统架构师。请先阅读项目中的 `前置约束.md`，然后为`MyVibeOS`完成第一阶段的“工程起步版”设计与实现。目标平台固定为QEMU模拟的`riscv64 virt`，运行模式为 OpenSBI + S-mode 内核，语言是 C + 少量 RISC-V 汇编。

设计目标：
1. 设计当前阶段的启动链与最小功能范围，运行模式固定为 OpenSBI + S-mode kernel。
2. 本阶段内核的所有终端输入、终端输出、启动日志、shell I/O、panic 输出，必须统一通过 OpenSBI 提供的控制台接口完成。
3. 严禁直接访问 UART/串口/MMIO 寄存器。
4. 严禁实现任何独立 UART 驱动、NS16550 驱动、串口轮询驱动或基于设备地址的 console 实现。
5. 如果 OpenSBI 控制台能力不足，也不要回退到 UART 方案；应明确说明限制，并保持架构约束不被破坏。
6. 实现最小 `kernel_main` 与 kernel shell 骨架。
7. 使用 RISC-V 汇编实现最小 boot 入口，完成栈初始化、清零 `.bss` 和跳转到 `kernel_main`。
8. 为 QEMU `riscv64 virt` 编写最小可用的 `linker.ld`，并明确关键段布局与链接符号用途。
9. 明确 `hartid`、设备树地址和关键链接符号如何传入内核。
10. 补齐 QEMU 运行命令，以及 `make run`、`make cscope`、`make clean` 的行为说明与验证点。
11. 在 kernel shell 中实现 `help`、`halt`、`dmesg` 命令，并保证后续新增命令时保留已有命令链。

验证要求：
1. 给出当前开发环境中的关键工具检查结论与缺失项清单。
2. 重点检查工具至少包括 `qemu`、RISC-V 交叉编译器、`make`、`objdump`、`gdb`、`cscope` 或 `ctags`。
3. 明确项目目录中已经建立了哪些约定子目录，哪些目录尚不存在但后续需要补齐。
4. 明确已经建立可扩展的根目录 `Makefile`、最小 boot 入口、`linker.ld`、最小 `kernel_main` 和 kernel shell 骨架。
5. 操作系统启动后必须进入kernel shell。
6. `help` 命令执行后必须显示所有kernel shell中已有的命令及命令的用途。
7. `dmesg` 命令执行后必须显示启动日志和最小内核运行日志，用于验证 OpenSBI 控制台与日志接口工作正常，并能体现启动横幅、当前 `hartid`、设备树地址或等效启动摘要信息。
8. `halt` 命令执行后关闭qemu模拟器。
