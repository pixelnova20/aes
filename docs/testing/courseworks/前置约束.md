# MyVibeOS前置约束

## 项目概况
- 当前项目名称固定为 `MyVibeOS`。
- `MyVibeOS` 是一个教学型 RISC-V 宏内核操作系统。

## 目标平台
- 唯一目标平台是 `QEMU` 模拟的 `riscv64 virt`机器。
- 运行模式固定为 `OpenSBI + S-mode kernel`。

## 工程目录约束
- 根目录应包含：
  - `kernel/`		//内核代码
  - `user/`            //用户代码
  - `libs/`            //用户态函数库
  - `build/`          //构建生成的二进制文件
  - `utils/`          //工具函数
  - `host-tools/`       //主机工具

- `kernel/` 下至少应包含：
  - `kernel/boot/`  	//包含启动相关的源代码
  - `kernel/hal/`        //包含硬件抽象层相关的源代码
  - `kernel/mm/`          //包含内存管理部分的源代码
  - `kernel/fs/`          //包含文件系统部分的源代码
  - `kernel/proc/`      //包含进程管理部分的源代码
  - `kernel/dev/`        //包含设备管理部分的源代码

- 根目录必须包含：
  - `Makefile`
  - `README.txt`

## Makefile 约束
- 根目录 `Makefile` 至少包含：
  - `run`
  - `cscope`
  - `clean`

### 目标行为
- `make run`
  - 编译整个内核
  - 调用 QEMU 启动系统

- `make cscope`
  - 为项目所有 C 和 ASM 源码生成 tag/cscope 文件
  - 生成文件放在仓库根目录

- `make clean`
  - 删除 `build/`
  - 删除根目录生成的 tag/cscope 文件

## 模块交付标准
- 能在当前模块范围内独立验收。
- 每一步都能通过 `make` / `make run` 或最小化自测验证

## 注意

- 如果发现主机平台是 Windows，你应该使用安装者提供的 WSL + Ubuntu 环境来构造 MyVibeOS。
- MyVibeOS工程的根目录是当前目录，即本文档所在的目录。
- 遇到职责边界不清时，先检查当前步骤提示词是否已经定义边界。
- 如果当前步骤提示词没有写清，一定要提出问题，等得到所提问题的答案后再编写代码。

## 本文件使用方式

将内容存成 `前置约束.md` 文件，并将该文件放置在工程的根目录。
