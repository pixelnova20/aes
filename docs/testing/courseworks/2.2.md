请设计并实现 `MyVibeOS` 的最小中断与时钟子系统：通用层 `irq.c` + 平台外部中断控制层 + 基于 SBI timer 的最小时钟中断路径。请先给设计说明，再给最小实现代码，再给验证方式，并说明已知限制。当前阶段只要求把外部中断控制路径和 SBI timer 路径抽象清楚，不要求引入具体平台部件命名。

设计目标：
1. 设计最小中断子系统的分层结构，明确通用层与平台外部中断控制层只负责外部中断的职责边界。
2. 实现 IRQ 注册、使能、屏蔽以及 claim/complete 的基本流程。
3. 接入基于 SBI timer 的最小时钟中断路径，并明确它与外部中断控制路径的边界。
4. 说明时钟中断初始化顺序、下一次时钟事件设置方式，以及时钟中断上下文里的安全边界。
5. 实现 tick 计数与最小上层时钟语义，并把时钟间隔设为 1000000 个 time 计数单位。
6. 补上 panic、assert、寄存器转储、错误日志和常见错误码解释组成的最小调试框架，但不要把 `dmesg` 作为本章新增命令重新引入。
7. 明确外部中断控制路径由 `MyVibeOS` 平台层负责，且它只处理外部设备中断；OpenSBI 不替内核管理这部分外部中断。
8. 在 kernel shell 中新增 `irqstat` 与 `ticks` 命令，并保留之前的命令。

验证要求：
1. 操作系统启动后必须进入 kernel shell。
2. `irqstat` 命令执行后必须显示已注册的 IRQ、使能状态和中断控制器摘要信息。
3. `ticks` 命令执行后必须显示当前 tick 计数以及最近一次时钟中断事件摘要。
4. 本步骤形成的 panic、assert 和错误日志必须能够通过现有日志路径输出，并与第一章已经引入的日志查看能力兼容，而不是重新定义一套新的日志入口。
